# Разделение голосов и слепки — план работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дать увидеть разные голоса внутри одной дорожки, назвать их по фрагментам и — отдельным осознанным шагом — узнавать тех же людей в следующих встречах.

**Architecture:** Диаризация живёт в своём крейте `meetingraft-diarize` за фичей, как whisper в `stt`: без фичи отдаётся заглушка, и весь остальной код собирается и проверяется на Linux. Пересбор (`ffi/rebuild.rs`) получает второй проход по дорожке, результат ложится в новую таблицу кластеров при версии Final. Слепки — отдельная глобальная таблица, включаемая настройкой.

**Tech Stack:** Rust (`meetingraft-domain`, `meetingraft-storage`, новый `meetingraft-diarize`, `meetingraft-ffi`), SQLite через `rusqlite`, SwiftUI.

Спека: `docs/superpowers/specs/2026-08-11-voice-clustering-design.md`.

## Global Constraints

- Комментарии и документация в коде — **по-русски**; сообщения коммитов — **по-английски** (`CLAUDE.md`).
- Тесты гонять по крейтам. Полный `cargo test` по workspace не влезает в память VPS.
- Перед коммитом: `cargo fmt --check && cargo clippy --all-targets -- -D warnings`. **Каждый коммит зелёный.**
- Swift собирается только на Mac. Задачи 6 и 7 уходят на проверку человеку; заявлять их проверенными нельзя.
- **Модель за фичей.** Без фичи крейт собирается и отдаёт заглушку. Иначе разработка на Linux встанет целиком, как встала бы с whisper.
- **Неопознанный остаётся неопознанным.** Ни один шаг не имеет права подписать реплику именем при слабом совпадении.
- Каждый тест обязан падать без своей ветки, и это проверяется возвратом дефекта.

### Task 2: `diarize-probe` — прибор до выводов

Третий прибор рядом с `echo-probe` и `gate-probe`, с той же
дисциплиной.

**Files:**
- Create: `rust/crates/diarize-probe/Cargo.toml`, `.../src/main.rs`
- Modify: `rust/Cargo.toml`

**Step 1: Заведомо положительный и заведомо отрицательный случай**

- [x] Положительный: два синтетических голоса, склеенных подряд, — прибор обязан найти смену
- [x] Отрицательный: один голос, разрезанный пополам, — смены быть не должно
- [x] Не разошлись — до настоящих данных дело не доходит, `ExitCode::FAILURE`

**Step 2: Чтение сессии**

- [x] Половина, ходящая в базу, проверяется отдельным тестом на заведомом случае
- [x] Печать: отрезки, метки, длительность каждого голоса, доля тишины

**Verification:** `cargo test -p meetingraft-diarize-probe`; сквозной прогон против засеянной базы

**Сделано 2026-08-11. Три вещи, которых не было в замысле.**

- **Прибор сегодня отказывает, и это его первый настоящий ответ.**
  `diarize_backend()` без модели отдаёт заглушку, заглушка отказывает,
  `self_check` печатает причину и выходит с `ExitCode::FAILURE`. Мерить
  нечем — сказано вслух, а не выведено читателем из пустой таблицы.
- **Положительный случай прибора доказан контролем, а не моделью.**
  В тестах живёт `PitchControl` — движок по частоте переходов через ноль,
  работающий ровно на синтетике из `self_check` и ни на чём больше. Без
  него «прибор красный» было бы неотличимо от «прибор красный всегда»:
  вердикт, который не бывает зелёным, ничего не проверяет.
- **Вердикт возвращает список причин, а не `bool`.** Первая версия
  отдавала цвет, и две ветки из четырёх снимались, **не покрасив ни
  одного теста**: отказ движка ловился проверкой «отрезков нет», а
  неверная граница — проверкой отрицательного случая, потому что двойник
  делил и там. Пятый случай за неделю, когда зелёный тест проверял не то.
  Теперь каждый тест утверждает свою строку вердикта, и снятие любой из
  четырёх веток красит ровно её тест — проверено снятием всех четырёх.

**Чего план не назвал, и это решено.** Прогнать прибор было нечем:
движка нет ни одного, а какой заводить — решала как раз задача 3. Круг
разорван выбором кандидата **до** замера — `sherpa-onnx`, первый в
таблице спеки. Сделано ниже, задачей 2.5.

### Task 2.5: sherpa-onnx за фичей — сделано 2026-08-11

Кандидат подключён, прибор на нём прогнан, числа сняты. **Всё на Linux:**
Мак для этой связки не нужен, в отличие от whisper.

- [x] `sherpa-onnx` 1.13 за фичей `model`, `SherpaDiarizer` на паре моделей
- [x] Поиск моделей на диске (`models/diarize/`), отказ называет
      недостающий файл
- [x] `scripts/fetch-diarize-models.sh` — модели и контрольные записи
- [x] Прибор судит движок по записям с известным числом людей
- [x] Сквозной прогон: сессия из базы → отрезки, метки, доли

**Что стоит эта связка.** Числа, а не впечатление: 15 статических
библиотек, 132 МБ распакованными (из них `libonnxruntime.a` — 109 МБ),
release-бинарь программы, зовущей только диаризацию, — **34.2 МБ**.
Линковщик неиспользуемое не выбрасывает: внутри лежат `OfflineTts`,
`espeak-ng`, `Kokoro` и второй распознаватель речи рядом с нашим whisper.
`cmake` при этом не нужен вовсе — `build.rs` качает готовые библиотеки,
то есть **сборка ходит в сеть**. На приложение сегодня не влияет: от
`diarize` зависит только прибор.

**Скорость: 0.08–0.18 от реального времени** (Linux VPS, CPU). Час
записи — 5–11 минут на канал. Число с Мака остаётся за задачей 3.

**Синтетика оказалась негодной.** Первый прогон: движок нашёл в двух
синтетических тонах речь, но счёл их одним голосом — и прибор напечатал
«смены движок не видит» про работающий движок. Тоны не речь, модель
голосов на них не работает. Прибор переписан на контроль записями с
известным ответом; синтетика осталась только для тестовых двойников.

**Порог кластеризации снят замером.** Умолчание крейта 0.5 разрывает
четверых на пятерых. Прогон по обеим записям дал единственное значение,
где обе сходятся точно, — **0.60**; таблица целиком в `sherpa.rs`. Это
одна машина и две чужие записи, то есть исходная точка, а не решение.

**Число голосов неустойчиво — и это не рост от объёма.** Контроль
удвоением дал 4 → 6, и первое прочтение было «зависит от количества
материала». Замер того же дня опроверг: та же запись **трижды** даёт
верные 4, а половины, переставленные местами при неизменной длине, — 5.
Случайности нет (тот же вход трижды подряд даёт 4, 4, 4), и это не
свойство движка вообще (запись с двумя далёкими голосами даёт 2 при любом
расположении). Остаётся неустойчивость на близких голосах.

Прибор поэтому проверяет устойчивость двумя перекладываниями: удвоением и
перестановкой половин. По одному удвоению вывод и вышел неверным.

**Причина найдена в тот же день, и она в модели.** Английская VoxCeleb
заменена на многоязычную CAM++ (zh+en) — неустойчивость ушла целиком:
трудная запись даёт 4 при любом расположении на всём плато 0.60…0.75.
Порог сдвинут на 0.65, в середину плато. По-русски не обучена ни одна из
двух моделей, так что перенос сюда один: неустойчивость — свойство
соответствия модели материалу, а не кластеризации.

### Task 3: Замер на настоящих встречах — сделано 2026-08-12

Гейт снят. Числа сняты на записи пользователя с ручной разметкой, и они
**опровергли основу остального плана**: кластеризация проиграла слепкам.

**Что померено.** Встреча на шестерых, две дорожки, 60 и 34 размеченные
человеком реплики.

| подход | результат |
|---|---|
| кластеризация, лучший порог | 81% совпадения, **14 голосов на шестерых** |
| слепки, порог 0.40, проверка на отложенной части | **94% подписано, 0% неверно** |
| слепки по всей встрече, порог 0.45 | подписано 77% mic и 87% system |

Размечено при этом было 17–21% времени. То есть **размечаешь пятую часть
— получаешь четыре пятых**, и ни одной неверной подписи на проверке.

**Три вещи, найденные попутно, каждая меняет план.**

1. **Покрытие сегментации — 67%**, и оно не двигалось ни на одном пороге
   кластеризации. Значит треть размеченного времени pyannote не считает
   речью вовсе. Границы из Final (ADR-011) этой болезни не имеют: они
   полны по построению.
2. **Речь попадает в обе дорожки, и насколько — пока не сосчитано.** Все
   шестеро нашлись и на `mic`, и на `system`, суммарная речь — 33 минуты
   на встрече в 22. Пользователь при этом видит повторяющиеся субтитры
   «нечасто, примерно 10–20%», а не сплошь. Две величины не сходятся, и
   разводить их надо замером, а не рассуждением: время, звучащее в обоих
   каналах, и текст, распознанный дважды, — разные вещи. Первое означало
   бы дефект захвата, второе — артефакт распознавания.
3. **`echo-probe` на этой же сессии говорил «эха нет»** (0.09 при пороге
   0.30). Два прибора разошлись, и это дороже любого из двух чисел.

**Осталось человеку** (и первое важнее всей остальной ветки):

- [x] **Послушать `mic` и `system` в одном месте по времени.** Отвечено
      замером вместо прослушивания (Epic 25, 2026-08-13): `diarize-probe
      --apply` нашёл один и тот же звук в 20 окнах из 22 при совпадении
      0.85…0.93. Направление обратное ожидаемому — не комната в `system`,
      а созвон в `mic`; следствия записаны в ADR-014
- [ ] Очная запись двух человек в один микрофон — случай, который канал
      не берёт по построению
- [ ] Время прохода и энергия (`scripts/measure-power.sh`) на Маке

### Task 4: ADR-013 — подпись голоса по слепку

Пишется **после** ответа про дублирование каналов: он решает, остаётся ли
канал источником истины вообще.

**Ответ получен 2026-08-13 — `ADR-014-call-in-the-microphone.md`.** Канал
остаётся источником истины там, где каналы несут разный звук; где несут
один и тот же (встреча через динамики) — атрибуция отказывается, а не
подписывает владельцем. Гейт снят, но роль диаризации сужена: она
разделяет голоса внутри дорожки и **эхо не лечит**. Копия чужой речи в
`mic` — не голос владельца, и подписывать её владельцем нельзя ни модели,
ни каналу.

**Написан 2026-08-13:** `docs/adr/ADR-013-voiceprint-speaker-labels.md`.

- [x] Уточняет ADR-012 там, где канал работает, и называет случай, где он
      не работает — обе дорожки с одним разговором. Порядок подписи
      назван жёстко: человек → канал → слепок
- [x] Фиксирует полосу отказа: неопознанный остаётся неопознанным. Два
      условия сразу — порог 0.45 и зазор 0.05, оба как умолчание, а не
      как константа
- [x] Фиксирует «ручное сильнее»: слепок не переписывает поставленное
      человеком
- [x] Фиксирует, что слепок не покидает машину, включая backend-путь
      (ADR-007)
- [x] **Разрешает вопрос, в какую сторону ошибаться** — в отказ. Вопрос
      «слить или разорвать» при слепках почти исчезает: ошибка идёт не
      туда и не туда, а в неподписанную реплику

**Про последний пункт.** Реплика пользователя 2026-08-11 — «во время
встречи не очень важно кто и что сказал, а после встречи можно и
разметить, и доразобрать» — подтверждает решение спеки о post-call, но
ломает обоснование правила «лучше слить двух, чем разорвать одного».

Спека выводила его из **заметности**: слияние слышно на первом же
фрагменте, дробление выглядит как правда. Если человек разбирает запись
осознанно, заметны оба, и решает **цена исправления**, а она смотрит в
другую сторону: слить два голоса — одно действие, разделить слитый —
работа по границам руками.

Замер добавил третье соображение, и оно сильнее обоих: при слепках вопрос
почти исчезает. Ошибка идёт не в слияние и не в дробление, а в **отказ**,
и отказ безобиден — реплика остаётся неподписанной и видна как есть.

### Task 5: Ядро — слепки поверх границ Final

**Переписано на числах.** Было «кластеры при пересборе»; кластеризация
проиграла и из плана уходит вместе с сегментацией pyannote.

Схема целиком: человек размечает несколько реплик → по ним складываются
слепки → слепки прогоняются по всем репликам Final → непохожее остаётся
неопознанным → человек размечает ещё → пересчёт. Обучения нет: слепок —
среднее по векторам, и добавление примеров стоит ноль.

- [ ] Миграция: слепок при встрече (вектор, идентификатор модели,
      секунды материала, число кусков). Идентификатор модели обязателен —
      векторы разных моделей несравнимы, и это уже стоило одной ошибки:
      смена модели не доехала до машины и замер шёл прежней
- [ ] Источник подписи у сегмента: канал, человек, слепок. Без него
      «ручное сильнее» неисполнимо — та же история, что с `EditOrigin` в
      Epic 19, где признак заводили задним числом ценой миграции
- [ ] Пересчёт слепков и подписей отдельной операцией, не в пересборе:
      он идёт минутами, а пересчёт слепков — секундами, и связывать их
      значит платить за дешёвое цену дорогого
- [ ] Граница FFI: пересчитать, список слепков, порог
- [ ] Порог по умолчанию 0.45 — середина измеренного окна 0.40…0.50

**Чего в этой задаче больше нет и почему:** таблицы кластеров (кластеров
нет), второго прохода сегментации (границы даёт Final), назначения
спикера кластеру (имя ставится реплике и через неё слепку).

**Verification:** тесты по крейтам; арифметика слепков уже покрыта в
`diarize::voiceprint`, а `diarize-probe --apply` служит образцом того, что
должно получиться в ядре.

### Task 7: Слепки между встречами

Ближе, чем было: считать их уже умеем, осталось решение о хранении.

- [ ] Настройка, выключенная по умолчанию, с прямым текстом о том, что
      именно сохраняется
- [ ] Область слепка: встреча (задача 5) против глобальной (эта)
- [ ] Сопоставление с полосой отказа; в полосе — в неопознанные, а не
      «наверное, он»
- [ ] Смена модели: сопоставление не выполняется, человеку сказано
      пересчитать. Идентификатор модели для этого уже хранится
- [ ] Удаление слепка одним действием; список слепков отдельно от списка
      записей
