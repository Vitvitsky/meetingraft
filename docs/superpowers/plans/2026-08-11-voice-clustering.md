# Разделение голосов и слепки — план работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Дать увидеть разные голоса внутри одной дорожки, назвать их по фрагментам и — отдельным осознанным шагом — узнавать тех же людей в следующих встречах.

**Architecture:** Диаризация живёт в своём крейте `meetingraft-diarize` за фичей, как whisper в `stt`: без фичи отдаётся заглушка, и весь остальной код собирается и проверяется на Linux. Пересбор (`ffi/rebuild.rs`) получает второй проход по дорожке, результат ложится в новую таблицу кластеров при версии Final. Слепки — отдельная глобальная таблица, включаемая настройкой.

**Tech Stack:** Rust (`meetingraft-domain`, `meetingraft-storage`, новый `meetingraft-diarize`, `meetingraft-ffi`), SQLite через `rusqlite`, SwiftUI.

Спека: `docs/superpowers/specs/2026-08-11-voice-clustering-design.md`.

## Global Constraints

- Комментарии и документация в коде — **по-русски**; сообщения коммитов — **по-английски** (`CLAUDE.md`).
- Тесты гонять по крейтам. Полный `cargo test` по workspace не влезает в память VPS.
- Перед коммитом: `cargo fmt --check && cargo clippy --all-targets -- -D warnings`. **Каждый коммит зелёный.**
- Swift собирается только на Mac. Задачи 6 и 7 уходят на проверку человеку; заявлять их проверенными нельзя.
- **Модель за фичей.** Без фичи крейт собирается и отдаёт заглушку. Иначе разработка на Linux встанет целиком, как встала бы с whisper.
- **Неопознанный остаётся неопознанным.** Ни один шаг не имеет права подписать реплику именем при слабом совпадении.
- Каждый тест обязан падать без своей ветки, и это проверяется возвратом дефекта.

## Гейт: задачи 4–7 детализируются после задачи 3

Первые три задачи существуют, чтобы решение о модели принималось на
измеренных числах. Пока замера нет, подробный план на ядро писать не на
чем: у разных связок разный выход (границы против границ + векторов),
и от этого зависит форма таблиц.

Это не отговорка, а то же правило, что уже дважды окупилось: догадка о
15% потерянных кадров оказалась артефактом измерения, а порог эха 0.60 —
потерей от рассогласования в один отсчёт.

### Task 1: Крейт `diarize` с границей и заглушкой

Ни одной модели. Тип результата, трейт движка, заглушка вместо него —
ровно как `stt::mock` до whisper.

**Files:**
- Create: `rust/crates/diarize/Cargo.toml`, `rust/crates/diarize/src/lib.rs`, `.../src/mock.rs`
- Modify: `rust/Cargo.toml` (члены workspace)

**Step 1: Что отдаёт диаризация**

- [ ] `VoiceTurn { start_ms, end_ms, cluster: u32 }` — отрезок речи с меткой голоса, без имени
- [ ] `DiarizeReport { turns, speakers_found, refused: Option<String> }` — отказ строкой, не пустым списком: ноль отрезков от сломанного движка выглядит как монолог
- [ ] Трейт `Diarizer` и `diarize_backend()` по образцу `stt_backend()`

**Step 2: Заглушка**

- [ ] Заглушка отдаёт **отказ**, а не выдуманные отрезки. Заглушка, притворяющаяся работающей, — та же убедительная неправда
- [ ] Тест: без фичи `diarize_backend()` даёт заглушку, и её отчёт содержит причину

**Verification:** `cargo test -p meetingraft-diarize`

### Task 2: `diarize-probe` — прибор до выводов

Третий прибор рядом с `echo-probe` и `gate-probe`, с той же
дисциплиной.

**Files:**
- Create: `rust/crates/diarize-probe/Cargo.toml`, `.../src/main.rs`
- Modify: `rust/Cargo.toml`

**Step 1: Заведомо положительный и заведомо отрицательный случай**

- [ ] Положительный: два синтетических голоса, склеенных подряд, — прибор обязан найти смену
- [ ] Отрицательный: один голос, разрезанный пополам, — смены быть не должно
- [ ] Не разошлись — до настоящих данных дело не доходит, `ExitCode::FAILURE`

**Step 2: Чтение сессии**

- [ ] Половина, ходящая в базу, проверяется отдельным тестом на заведомом случае
- [ ] Печать: отрезки, метки, длительность каждого голоса, доля тишины

**Verification:** `cargo test -p meetingraft-diarize-probe`; сквозной прогон против засеянной базы

### Task 5: Ядро — кластеры при пересборе (без слепков)

Форма таблиц зависит от задачи 3, поэтому шаги здесь крупные.

**Verification:** тесты по крейтам; известный дефект возвращается и тест краснеет

### Task 6: Список голосов на вкладке Speakers

То, что описано в просьбе дословно. **Swift — проверяет человек.**

- [ ] Неопознанные голоса отдельным разделом: длительность, число реплик, фрагмент
- [ ] Прослушивание — тем же проигрывателем, что у реплики
- [ ] Имя присваивается голосу, а не реплике; после этого голос уходит из неопознанных
- [ ] Ловушка: `SpeakerAttributionCoreProviding` реализуют тестовые дубли — новый метод протокола ломает сборку тестовой цели на Маке. Добавлять сразу с заглушками

---

### Task 7: Слепки между встречами

Отдельно и позже всего: биометрия включается осознанно.

- [ ] Настройка, выключенная по умолчанию, с прямым текстом о том, что хранится
- [ ] Таблица слепков: вектор, идентификатор модели, длительность материала
- [ ] Сопоставление с полосой отказа; в полосе — в неопознанные, а не «наверное, он»
- [ ] Смена модели: сопоставление не выполняется, человеку сказано пересчитать
- [ ] Удаление слепка одним действием; список слепков отдельно от списка записей
- [ ] Подпись по слепку отличается в интерфейсе от подписи человеком

## Что этот план сознательно не содержит

- Живой диаризации: бюджет живого пути расписан по миллисекундам (ADR-010).
- Автоматического имени: система не угадывает, кого зовут Пётр.
- Облачного пути: голос с машины не уходит.
