# Phase 10 — Final v2: re-ASR и полировка

Детальный план фазы. Основание: `docs/product-ux-review-2026-08-03.md`
§3.1 и решение 2026-08-03 (re-ASR, затем LLM-полировка).

## Исходное состояние

`rust/crates/postcall/src/assemble.rs:11-16` — Final это
`filter(Final).map(normalize).join("\n\n")` над live-финалами. Тот же
текст с подставленными терминами: без пунктуации, абзацев, тайм-кодов и
спикеров. Вкладка **Compare** показывает две почти идентичные панели и
обесценивает саму идею второго прохода, а версионирование Final
версионирует одну и ту же операцию над одними и теми же данными.

Аудио-чанки сохраняются по ADR-006 и разделены по каналам (ADR-004,
ADR-009) — вход для настоящего прохода уже есть.

## Exit criteria

- На реальной русской встрече Final заметно точнее Live и читается
  абзацами.
- Compare показывает осмысленную разницу, а не два одинаковых текста.
- Каждый сегмент Final знает свой канал точно — без эвристики
  доминирования, которой пользуется live.
- Проход идёт фоново, с прогрессом и отменой, и не блокирует запись
  следующей встречи.
- Недоступный LLM не портит результат молча: Final остаётся результатом
  re-ASR, provenance это называет.

## Решения по проходу

**Решено 2026-08-03.**

1. **Модель качается по требованию** при первом пересборе Final. Тянуть
   1.5 ГБ на онбординге ради функции, которой могут не воспользоваться, —
   плохой обмен.
2. **Проход идёт локально.** Следует из позиционирования: local-first —
   единственный аргумент, проходящий через службу безопасности. Backend
   WhisperX остаётся вторым путём за тем же контрактом (T7).

## T1 — чтение сохранённых чанков — **сделано**

`read_session_pcm(session_id, channel)`. Дополнительно ловится обрезанный
файл: manifest хранит ожидаемое число кадров, поэтому расхождение — явная
ошибка `ChunkTruncated`, а не тихо укоротившийся транскрипт.


- `AudioManifestStore::read_session_pcm(session_id, channel) -> Vec<i16>`
  — склейка чанков в порядке `seq` по путям из `audio_manifest`.
- Каналы читаются **раздельно**: ровно ради этого ADR-009 держит их
  раздельными на диске.
- Отсутствующий файл — ошибка, а не молчаливая тишина в середине записи.
- Тесты: собранный поток равен записанному; пропуск файла даёт ошибку;
  пустая сессия даёт пустой поток, а не панику.

Коммит: `feat: чтение PCM сессии из manifest`.

## T2 — batch-режим распознавания — **сделано** (инференс не проверен)

`BatchTranscriber` + `MockBatchTranscriber` (36 тестов проходят на Linux)
+ `WhisperBatchTranscriber` за фичей: beam search, температурный фолбэк,
контекст между окнами, сегментация самой моделью. Компилируется и
линтуется здесь; качество прохода на реальном аудио — только на Mac.

Решения по открытым вопросам приняты 2026-08-03: модель качается **по
требованию** при первом пересборе, проход идёт **локально**; backend
WhisperX остаётся вторым путём (T7).

Контракт отдаёт прогресс и принимает отмену возвратом `false` — это
понадобится джобу в T6, и закладывать позже было бы переделкой сигнатуры.


Отдельный контракт, а не расширение `SttEngine`: у batch другой режим
работы (нет потоковости, есть тайм-коды, допустимы медленные настройки).

- `trait BatchTranscriber { fn transcribe_all(&mut self, pcm: &[i16],
  sample_rate: u32) -> Result<Vec<TranscriptSegment>, String> }`.
- `TranscriptSegment { start_ms, end_ms, text }`.
- Whisper без realtime-ограничений: `single_segment(false)`,
  `no_context(false)`, тайм-коды включены, beam search вместо greedy,
  temperature fallback при низком `avg_logprob`.
- Модель берётся отдельно от live: picker «Post-call STT»
  (`SettingsView.swift:115`) наконец получает содержательные варианты.
- Тесты идут на Mock-реализации: Whisper за feature flag и в CI не
  гоняется.

Коммит: `feat: batch-контракт распознавания и Whisper-реализация`.

## T3 — сегменты в домене и хранилище — **сделано**

Миграция 5, `domain::FinalSegment`, `replace_final_segments` /
`list_final_segments`, чистка в `delete_meeting`. Замена, а не вставка:
пересбор той же версии обязан давать тот же результат, а не удваивать
сегменты. `speaker_id` заведён сразу пустым — Phase 11 его заполнит без
изменения схемы.


Markdown как единственное представление не годится: Phase 11 привяжет
спикера к сегменту, а по markdown это невозможно без парсинга
собственного формата обратно.

- Миграция 5: `final_segments (meeting_id, version, idx, start_ms,
  end_ms, channel, speaker_id, text)`, индекс по `(meeting_id, version,
  idx)`.
- `FinalTranscript.body_markdown` остаётся — это рендер для экспорта и
  вход для артефактов.
- `speaker_id` заводится сразу пустым: Phase 11 его заполнит, схему
  менять не придётся.
- Тесты: запись и чтение сегментов сохраняют порядок и границы; удаление
  встречи чистит и сегменты (дополнить `delete_meeting`).

Коммит: `feat: сегменты финального транскрипта в хранилище`.

## T4 — слияние каналов без эвристики — **сделано**

`postcall::merge_channels` сводит дорожки по времени, перекрытия остаются
оба. Порядок сортировки задан полностью (время → канал → длительность),
чтобы результат не зависел от реализации `sort`.

Рядом `render_segments`: markdown из сегментов, где смена говорящего
всегда разрывает абзац. `TranscriptSegment` переехал в `domain` — это
общий словарь движка и сборки, иначе `postcall` пришлось бы зависеть от
`stt`.


- Каждый канал распознаётся отдельно → канал сегмента известен точно.
- Две дорожки сливаются в один хронологический список по `start_ms`.
- Перекрытия (говорят одновременно) сохраняются оба: это факт встречи, а
  не ошибка. В live такой сегмент достался бы одному каналу.
- Тесты: непересекающиеся дорожки чередуются; полное перекрытие
  сохраняет оба сегмента; пустой системный канал даёт монолог.

Коммит: `feat: слияние дорожек в хронологию с точной атрибуцией`.

## T5 — LLM-полировка

- Промпт в `postcall/src/prompts.rs`: расставить пунктуацию и абзацы, не
  менять смысл, не добавлять того, чего не было. Термины глоссария — в
  промпт.
- Обработка батчами по сегментам (контекстное окно), границы сегментов и
  тайм-коды **сохраняются**: полировка меняет текст внутри сегмента, а не
  его положение во времени.
- **Без тихого фолбэка**: недоступный LLM оставляет Final результатом
  re-ASR, и provenance это называет. Молча отдавать непричёсанный текст
  под видом отполированного — та же ошибка, что нынешний Final под видом
  рефайнмента.
- Тесты: пустой вход; ошибка LLM не теряет транскрипт; число сегментов на
  выходе равно числу на входе.

Коммит: `feat: LLM-полировка сегментов Final`.

## T6 — фоновый джоб с прогрессом и отменой

UniFFI синхронный, а проход идёт минутами.

- `start_final_rebuild(meeting_id) -> job_id`,
  `final_rebuild_progress(job_id) -> FfiRebuildProgress { state, done,
  total, error }`, `cancel_final_rebuild(job_id)`.
- Поток внутри Rust, состояние под мьютексом; отмена проверяется между
  сегментами.
- Запись новой встречи имеет приоритет: если стартует `start_recording`,
  идущий rebuild притормаживается, а не конкурирует за CPU с live-STT.
- Тесты на state machine джоба: happy path, отмена в середине, ошибка,
  повторный старт при активном джобе.

Коммит: `feat: фоновый пересбор Final с прогрессом и отменой`.

## T7 — backend WhisperX как альтернативный путь

- Та же `BatchTranscriber` за HTTP: `postCallStt` выбирает
  `local_whisper_large` | `backend_whisperx`.
- Механика job на backend уже есть (`submit_backend_job`), расширяется
  вид работы.
- WhisperX даёт word-level alignment — он потребуется Phase 11, поэтому
  формат сегментов проектируется под него сразу.
- Тесты: маппинг ответа backend в `TranscriptSegment`; недоступный
  backend даёт ошибку, а не пустой транскрипт.

Коммит: `feat: backend WhisperX как второй путь re-ASR`.
