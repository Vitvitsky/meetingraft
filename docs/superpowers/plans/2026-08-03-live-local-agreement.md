# Live: стабилизация субтитров через LocalAgreement-2

Слайс live-пути, не входит в нумерованные фазы. Основание: текущий
`WhisperSttEngine` уже перегоняет растущий буфер через Whisper раз в
секунду, но не извлекает из этого пользы.

## Что не так сейчас

`rust/crates/stt/src/whisper.rs`:

- **Весь сегмент остаётся `Partial` до тишины** (`push_pcm:145`). Строка
  целиком переписывается на каждой итерации — глазом это читается как
  мерцание, а не как уточнение.
- **Буфер не обрезается.** Он растёт весь сегмент речи: минутный монолог
  означает транскрибирование шестидесяти секунд аудио каждую секунду.
  Работа квадратичная, бюджет `partial ≤ 2.0 s` из `architecture.md` на
  этом не держится.
- **Контекст не переиспользуется**: `set_no_context(true)`,
  `set_single_segment(true)`, `set_print_timestamps(false)`.

## Приём

**LocalAgreement-2** (Macháček et al., 2023, «Turning Whisper into
Real-Time Transcription System»): держим две последние гипотезы по
растущему буферу, берём их наибольший общий префикс и объявляем его
окончательным; расходящийся хвост показываем как неустойчивый.

Свойство, ради которого всё делается: **зафиксированное не меняется**.
Коммитим только то, с чем independently согласились две итерации подряд,
поэтому `Final` остаётся неизменяемым, а исправление ошибки происходит в
хвосте, который ещё не зафиксирован.

Это ложится на существующую модель событий без её изменения:
`LiveCaptionsViewModel.append` уже заменяет последний `Partial`.

## Что это не решает

Не заменяет post-call второй проход (Phase 10). Live даже со
стабилизацией ограничен маленькой моделью и куском аудио; post-call
берёт большую модель, полный контекст и оба канала раздельно. Но
стоимость несопоставима: здесь дни, там недели, а эффект пользователь
видит на первой же встрече.

## Exit criteria

- Зафиксированный текст в ленте не переписывается задним числом.
- Буфер ограничен сверху; длина монолога не влияет на время инференса.
- Бюджет `partial ≤ 2.0 s` соблюдается на монологе длиннее минуты.
- Правка последнего слова после появления контекста видна в ленте.

## T1 — тайм-коды и сегменты из whisper-rs — **сделано** (компилируется и линтуется)


Без них нечем резать буфер: обрезка идёт по границе зафиксированного
префикса.

- В `transcribe` включить `set_print_timestamps(true)`, снять
  `set_single_segment(true)`.
- Внутренний тип `Hypothesis { segments: Vec<HypothesisSegment> }`,
  `HypothesisSegment { start_ms, end_ms, text }` из
  `segment.start_timestamp()` / `end_timestamp()`.
- Фильтрация галлюцинаций и `no_speech_probability` остаётся посегментной.
- Тест: синтетический ответ движка (без реального Whisper) разбирается в
  сегменты с монотонными границами.

Коммит: `feat: сегменты с тайм-кодами из whisper-rs`.

## T2 — общий префикс двух гипотез — **сделано**

`stt::local_agreement`, 27 тестов; сборка слов из токенов покрыта отдельно.


Чистая функция, целиком тестируемая без модели.

- `fn agreed_prefix(previous: &[Token], current: &[Token]) -> usize` —
  длина наибольшего общего префикса.
- Сравнение по **словам после нормализации** (регистр, пунктуация по
  краям), а не по символам: Whisper переставляет запятые между
  итерациями, и посимвольное сравнение почти никогда не сойдётся.
- Тесты: полное совпадение; расхождение в последнем слове; расхождение в
  середине; пустая предыдущая гипотеза; изменение только пунктуации не
  ломает согласие.

Коммит: `feat: наибольший общий префикс гипотез для LocalAgreement`.

## T3 — фиксация префикса и события — **сделано**


- Движок держит `committed: Vec<Token>` и `previous_hypothesis`.
- На каждой итерации: новая гипотеза → `agreed_prefix` с предыдущей →
  всё, что дальше уже зафиксированного, уходит `Final`; остаток —
  `Partial`.
- `flush` фиксирует остаток целиком (конец речи — контекста больше не
  будет).
- Тесты: последовательность из трёх гипотез даёт ожидаемую цепочку
  `Final`/`Partial`; зафиксированный текст не появляется повторно.

Коммит: `feat: фиксация стабильного префикса live-субтитров`.

## T4 — обрезка буфера — **сделано**


- После фиксации префикса аудио до `end_ms` последнего зафиксированного
  сегмента выбрасывается из буфера.
- Жёсткий потолок буфера (~30 с — окно Whisper): если согласия долго нет,
  фиксируем принудительно и режем, иначе латентность уходит.
- Тест: длинная серия push не увеличивает размер буфера сверх потолка.

Коммит: `feat: обрезка буфера по зафиксированному префиксу`.

## T5 — зафиксированный префикс как контекст — **откачено**

На реальной речи дало петлю повторений: Whisper пересказывал промпт, и
зафиксированный текст возвращался как новая гипотеза. Разбор — в ADR-010,
раздел «Откат». В промпт идёт только глоссарий.


- Снять `set_no_context(true)`; последние N токенов зафиксированного
  текста подмешивать к `initial_prompt` рядом с глоссарием.
- Порядок важен: глоссарий — термины, префикс — непосредственный
  контекст; при конфликте за длину промпта режется префикс.
- Тест: промпт содержит и термины глоссария, и хвост зафиксированного.

Коммит: `feat: зафиксированный префикс в контекст декодирования`.

## T6 — замер и ADR — **сделано**

Замеры сняты на M4 Max с `ggml-base`: инференс 91–151 мс без роста от
длины реплики, буфер ограничен 1100–2700 мс, фиксация через одну
итерацию. Числа и разбор наблюдаемого цикла — в ADR-010.


- Замер до/после на реальной записи: время инференса на итерацию,
  задержка появления `Partial`, задержка фиксации `Final`. Числа — в ADR,
  не в коммит-сообщение.
- **ADR-010 «LocalAgreement для live-субтитров»**: приём, почему
  посегментное сравнение по словам, потолок буфера, размен «задержка
  фиксации против стабильности».
- `docs/architecture.md`: бюджет латентности дополнить строкой
  «фиксация final после согласия двух гипотез».

Коммит: `docs: ADR-010 и замеры LocalAgreement`.

## Порядок

T1 → T2 → T3 → T4 → T5 → T6. T2 не зависит от Whisper и делается первым,
если нужен быстрый прогресс без Mac.

**Проверено полностью:** компилятор, clippy и тесты логики на Linux,
поведение на реальной речи — замерами на Mac (T6).

## Риски

| Риск | Решение |
|------|---------|
| Согласие не наступает на шумной речи | Принудительная фиксация по потолку буфера (T4) |
| Тайм-коды whisper-rs неточны на границах | Резать с запасом назад (~200 мс), потеря контекста дешевле обрыва слова |
| Рост CPU от более частых итераций | Шаг итерации остаётся ~1 с; выигрыш даёт обрезка буфера, а не частота |
| Адаптер `whisper.rs` не собирается вне Mac | Решено: ускоритель выбирается по платформе (Metal / CPU), на Linux нужен только `cmake`. `cargo check`, `clippy` и тесты с `--features whisper` проходят |
| Служебные токены попадают в текст | Отбрасываются по `token_id() >= token_eot()` — иначе тайм-коды `<\|1.20\|>` стали бы «словами» |
