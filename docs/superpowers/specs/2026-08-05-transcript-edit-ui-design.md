# Epic 19 — интерфейс правки транскрипта

Дата: 2026-08-05. Основание: `docs/backlog.md`, Epic 19.
Продолжает `2026-08-04-epic-19-transcript-edits-design.md` (ядро, PR #31).

## Задача

Ядро правки слито и работает: `edit_segment_text` сохраняет правку,
удаляет её при возврате к исходному тексту и **сам заводит подсказку в
глоссарий**. Журнал переживает пересбор, неприменившиеся правки
собираются отдельным списком, фрагмент аудио отдаётся по диапазону.

Показать всё это некому. В приложении нет ни правки на месте, ни
пометки правленого сегмента, ни раздела неприменившихся правок, ни
кнопки «заменять всюду». Работа сделана и не приносит ничего.

Эта спека закрывает интерфейс и дозакрывает границу FFI там, где её не
хватает.

## Что решено

**Правка раскрывается в строке** (вариант A из разбора 2026-08-05).
Клик по тексту превращает его в поле; под полем — полоска с
воспроизведением фрагмента, «вернуть исходное» и «заменять всюду», ниже
— что распознала модель.

Соседняя функция на этом же экране, переназначение спикера, сделана
ровно так, и причина записана в `FinalSegmentsView.swift`: правка живёт
там, где ошибка видна, иначе человека заставляют помнить номер реплики.
Инспектор справа делил бы неширокое окно ради текста, который нужен
только когда правка уже есть.

**Неприменившиеся правки — баннер над списком Final**, появляется
только когда они есть, разворачивается на месте. Отдельная вкладка была
бы пустой почти всегда, а это заглушка в интерфейсе. Секция в конце
списка прячет сообщение «часть твоей ручной работы отвалилась» за час
прокрутки — такое должно попадаться на глаза само.

## Отвергнуто: ручной перенос правки

В первом наброске у неприменившейся правки была кнопка «найти место
вручную» — привязать её к сегменту новой версии. Она не выживает.

`original_text` несёт две роли: по нему правка ищет себя при пересборе и
по нему же определяется возврат к исходному. Привязка к сегменту, у
которого распознано другое, записала бы в журнал неправду — «модель
сказала здесь X», когда она сказала Y. После этого «вернуть исходное»
требовало бы текста, которого человеку никто не показывал: ровно тот
дефект, от которого уже защищается фильтр по версии
(`ffi/src/lib.rs:1511–1522`).

Честно это делается только переписыванием `original_text` под целевой
сегмент — то есть заведением на нём новой правки. Ручной перенос
схлопывается в «скопировать свой текст и поправить нужный сегмент», и
это уже работает.

Действия у неприменившейся правки: **прослушать**, **скопировать
текст**, **удалить**.

## Границы FFI

Меньше, чем казалось: два поля и один метод.

### Поля в `FfiFinalSegment`

Рядом с существующим `text_edited`.

| Поле | Смысл |
|---|---|
| `original_text: String` | что распознала модель; пусто, если правки нет |
| `promotable_term_id: String` | id подсказки, родившейся из этой правки; пусто, если термина нет или он уже замена |

`original_text` даёт и показ «было», и кнопку «вернуть исходное»: она
вызывает существующий `edit_segment_text` с этим текстом, а тот сам
удаляет правку из журнала. Отдельный метод не нужен.

`promotable_term_id` заполняет Rust — он же решает, показывать ли
кнопку. В Swift не уезжает ни разбор диффа (`term_from_edit`), ни знание
про виды записи глоссария. Термин чужой встречи в поле не попадает:
`term_applies_to_meeting` уже задаёт это правило для
`promote_term_to_replacement`, и поле обязано ему следовать — иначе
кнопка предложит замену, которая в этой встрече не применится.

**Почему поля, а не методы.** Строка правится и перерисовывается на
месте, значит данные нужны при каждой отрисовке сегмента, а не один раз
после нажатия. Полем это приезжает вместе с сегментом; методом — сетевым
по объёму запросом на каждую строку списка.

### Метод

```
delete_segment_edit(edit_id: String) -> String
```

Снимает неприменившуюся правку из баннера. Пустая строка — успех, как у
соседей. `FfiSegmentEdit` уже отдаёт `id`, в хранилище
`delete_segment_edit` уже есть — это тонкая обёртка.

`promote_term_to_replacement` не меняется: он уже принимает
`(term_id, meeting_id, version)` и сам проверяет область действия.

## Поведение

### Когда правка сохраняется

По Enter или по потере фокуса. Esc откатывает. **Не по нажатию
клавиши.**

Причина не в стиле: `edit_segment_text` делает четыре чтения из SQLite,
планирование, до двух записей и в конце `rerender_final_bodies`, который
перерисовывает markdown **всех версий** встречи (`ffi/src/lib.rs:437`).
Сохранение на каждый символ означало бы полную перерисовку транскрипта
на каждый символ.

### «Заменять всюду» требует подтверждения

`promote_term_to_replacement` вызывает `occurrences_to_edit`
(`ffi/src/lib.rs:1658`) и заводит **обычные записи журнала**. Каждая
затронутая реплика получает ту же пометку «правка», как будто человек
набрал её руками, и становится невосприимчивой к будущим массовым
заменам. Отменить одно нажатие можно только посегментно.

Это открытый пункт бэклога («массовая замена неотличима от ручной
правки»), и здесь он не чинится: нужен признак источника правки — новое
понятие в предметной области.

Промолчать при этом нельзя. Кнопка спрашивает подтверждение и **словами
называет последствие**: затронет все совпадения в этой встрече, каждая
изменённая реплика будет помечена как правка. Числа не показываем — для
него нужен сухой прогон отдельным методом, а формулировки достаточно,
чтобы не нажать вслепую.

### Проигрывание фрагмента

`segment_audio` отдаёт сырой PCM i16 little-endian моно и частоту
дискретизации; потолок 30 секунд стоит в ядре. Swift собирает
`AVAudioPCMBuffer` и играет через `AVAudioPlayerNode`.

`sample_rate == 0` означает, что записи за этот диапазон нет — кнопка
воспроизведения **не показывается вовсе**, а не показывается нерабочей.

## Экран

Всё садится в `FinalSegmentsView` и `SpeakerAttributionViewModel` —
туда же, где переназначение спикера.

Контракт `SpeakerAttributionCoreProviding`
(`SpeakerAttributionViewModel.swift:5`) уже отдаёт `listFinalSegments`;
добавляются `editSegmentText`, `listUnappliedEdits`,
`deleteSegmentEdit`, `promoteTermToReplacement`, `segmentAudio`.
Протокол — то, почему presentation model тестируется поддельным ядром
без Rust; практика в проекте уже заведена
(`SpeakerAttributionViewModelTests`, `FinalRebuildViewModelTests`).

Проигрывание — **отдельный маленький объект**, а не метод presentation
model: он держит `AVAudioEngine` и должен пережить перерисовку списка.
Внутри модели аудиодвижок дёргался бы на каждое обновление строки.

Бизнес-логики в слое интерфейса нет (`AGENTS.md`): наложение журнала,
извлечение терминов, проверка области действия и сопоставление при
пересборе живут в Rust.

## Тесты

### Rust — собирается и проверяется без Mac

- `original_text` отдаётся распознанным для правленого сегмента и
  пустым для неправленого. **Ловушка:** если в данных правленый и
  распознанный тексты совпадут, тест пройдёт, ничего не проверив —
  они должны различаться заведомо;
- `promotable_term_id` непуст, когда из правки родилась подсказка,
  действующая во встрече;
- `promotable_term_id` пуст, когда термина нет (правка длиннее трёх
  слов с любой стороны);
- `promotable_term_id` пуст, когда термин **уже** замена. **Ловушка:**
  случай требует настоящей замены в данных, иначе проходит вхолостую;
- термин чужой встречи в `promotable_term_id` не попадает;
- `delete_segment_edit` сносит неприменившуюся правку и не задевает
  применённые.

По каждому пункту сперва падающий тест. Epic 19 споткнулся на этом
трижды: тест был зелёным, обходя проверяемое условие стороной.

### Swift — уходит на проверку человеку

Тесты presentation model на поддельном ядре: раскрытие и схлопывание
строки, вызов сохранения по Enter и по потере фокуса, откат по Esc,
показ баннера только при непустом списке, скрытие кнопки
воспроизведения при `sample_rate == 0`, скрытие «заменять всюду» при
пустом `promotable_term_id`.

Сборка и прогон — только на Mac (`scripts/verify-mac.sh`).

## Чего в этой работе нет

- **Автопредложения правок** по уверенности Whisper — исключены
  исходной спекой ядра;
- **правка живых субтитров** — только post-call, там же;
- **сжатие словаря через LLM** — `compress_hints` / `apply_compression`
  описаны в спеке ядра, но в ядре их нет;
- **признак источника правки**, отличающий массовую замену от ручной —
  открытый пункт бэклога, новое понятие в предметной области;
- **пометка устаревших артефактов** — вынесена в Epic 8 решением
  2026-08-05: `artifacts` не хранит связи с версией Final, и это про
  версионирование артефактов, а не про правку;
- **чистка журнала правок** — открытый пункт бэклога, решение уровня
  продукта.
