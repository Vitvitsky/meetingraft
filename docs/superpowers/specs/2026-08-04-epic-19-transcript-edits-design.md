# Epic 19 — Правка распознанного на месте с пополнением глоссария

Дата: 2026-08-04. Основание: `docs/backlog.md`, Epic 19.

## Задача

Глоссарий влияет на качество распознавания напрямую — через
`initial_prompt` он смещает Whisper (Phase 5). Но наполняется он вручную
и поэтому пустует: чтобы завести термин, человеку надо понять схему —
что такое surface, что такое canonical, чем они отличаются.

При правке прямо в транскрипте объяснять нечего: **распознанный текст и
есть surface, введённый — canonical**. Оба поля заполняются из действия.
Замыкание этого контура и есть содержание работы.

## Что решено

Правка живёт **отдельным журналом поверх версий транскрипта**, а не в
таблице сегментов. Сегменты остаются производными от распознавания.

Глоссарий получает **два вида записи**. Подсказка рождается из правки
автоматически, замена требует явного жеста. Это закрывает найденный
ранее дефект схемы: одна форма обслуживала два разных намерения —
«исправляй вот так» и «просто знай такое слово».

Разделение необходимо, потому что `normalize_caption`
(`rust/crates/glossary/src/normalize.rs`) заменяет **безусловно и
везде**: нашёл surface — подставил canonical, без оглядки на контекст.
Термин, родившийся из грамматической правки («пошли» → «пошёл»),
превратился бы в глобальную замену и переписывал бы все будущие тексты.
Подсказка такого сделать не может: цена ошибки в `initial_prompt` —
чуть смещённое распознавание, и она обратима.

## Данные

### Журнал правок

Новая таблица `segment_edits`:

| Поле | Смысл |
|---|---|
| `id` | uuid |
| `meeting_id` | встреча |
| `channel` | микрофон / система |
| `start_ms`, `end_ms` | диапазон исходного сегмента |
| `original_text` | что распознала модель |
| `edited_text` | что ввёл человек |
| `created_at` | момент правки |
| `applied_version` | версия, в которой правка сейчас применена; `NULL` — не применилась |

Индекс по `(meeting_id, applied_version)` — чтение сегментов версии
идёт по нему.

### Вид записи глоссария

В `GlossaryTerm` (`rust/crates/domain/src/glossary.rs`) добавляется:

```rust
pub enum GlossaryKind {
    /// Только подсказка Whisper. Текст не переписывает.
    Hint,
    /// Замена surface → canonical в готовом тексте.
    Replacement,
}
```

Миграция добавляет колонку `kind INTEGER NOT NULL DEFAULT 1`, где `1` —
`Replacement`: существующие термины ведут себя как раньше.

Уникальный индекс `(surface, language, scope, ifnull(meeting_id, ''))`
не меняется. Повышение подсказки до замены — это `UPDATE kind`, а не
вторая строка.

Поведение движка (`rust/crates/glossary/src/engine.rs`):

- `normalize_caption` берёт только `Replacement`;
- `build_whisper_prompt` берёт оба вида — он и так фильтрует пустые
  `canonical`, а у подсказки `canonical` заполнен введённым словом.

## Как правка живёт

**Сохранение.** Запись в журнал с диапазоном и обоими текстами,
`applied_version` = текущая версия транскрипта.

**Чтение.** `list_final_segments` накладывает правки версии поверх
текста сегментов. Правленый сегмент помечен — интерфейс это показывает.

**Пересбор.** Для каждой правки ищется сегмент новой версии, который
перекрывается по времени **и** содержит `original_text`:

- нашёлся ровно один — текст заменяется, `applied_version` обновляется;
- нашлось несколько — берётся тот, у кого больше перекрытие по времени;
- не нашёлся — `applied_version` становится `NULL`.

Неприменившиеся правки видны отдельным разделом с исходным и новым
текстом. Ничего не пропадает молча — это главное требование к механике.

## Глоссарий из правок

`diff_words` (`rust/crates/postcall/src/diff.rs`) достаёт из пары
`original_text` / `edited_text` заменённые цепочки слов.

**Автоматически.** Замена становится `Hint` в области встречи, если
**обе** её стороны — до трёх слов включительно. Вопросов человеку не
задаётся: словарь должен наполняться сам, иначе он снова будет
пустовать. Всё, что длиннее хотя бы с одной стороны, — правка смысла, а
не словарная, и термином не становится.

**По жесту.** Рядом с правкой — одна кнопка «заменять всюду». Она
переводит `Hint` в `Replacement` и применяет ко всем вхождениям в этой
же встрече. Опасное действие требует явного жеста, безопасное не требует
ничего.

**Повышение до глобального.** При повторе той же пары
`surface`→`canonical` в другой встрече — сравнение без учёта регистра,
как в `normalize`:

- `Hint` повышается в глобальную область сам;
- `Replacement` — предлагается, решает человек.

Логика та же: то, что не переписывает текст, не требует подтверждения.

## Сжатие словаря

Отдельная операция через существующий `llm_http`
(`rust/crates/postcall/src/llm_http.rs`, рабочий HTTP-клиент).
`local_llm.rs` для этого непригоден — это заглушка на 23 строки.

Работает **только по `Hint`** и **по всему словарю сразу**, а не по
одной встрече: дубли и формы одного слова копятся именно между
встречами. Объединяет формы, выбрасывает мусор. `Replacement` не
трогает — это то, что человек подтвердил руками.

Результат не применяется молча. Показывается список «убрать /
объединить», человек подтверждает. Молча удалять наработанное нельзя,
даже если удаляет модель.

## Интерфейс

Экран сегментов Final (Phase 11, T5) дополняется:

- проигрывание фрагмента сегмента через существующий `segment_audio`;
- правка текста на месте;
- пометка правленого сегмента;
- кнопка «заменять всюду» рядом с правкой;
- раздел «правки не применились» после пересбора.

Бизнес-логики в слое интерфейса нет: наложение журнала, извлечение
терминов и сопоставление при пересборе живут в Rust и отдаются через
FFI.

## Границы FFI

Новое в `rust/crates/ffi/src/lib.rs`:

- `edit_segment_text(meeting_id, version, index, text) -> String` —
  ошибка строкой, как у соседних методов. Текст, совпавший с исходным
  распознаванием, **удаляет** правку из журнала: возврат к исходному —
  это отмена, а не ещё одна правка;
- `list_unapplied_edits(meeting_id) -> Vec<FfiSegmentEdit>`;
- `promote_term_to_replacement(term_id) -> String`;
- `compress_hints() -> FfiCompressionPlan` и
  `apply_compression(plan: FfiCompressionPlan) -> String`. План никуда
  не сохраняется — он возвращается в приложение, показывается человеку и
  приходит обратно целиком.

`FfiFinalSegment` получает поле `text_edited: bool`.

## Тесты

Rust — всё существенное, собирается и прогоняется без Mac:

- наложение журнала на версию: правленый текст возвращается вместо
  распознанного;
- сопоставление при пересборе: нашлось / не нашлось / несколько
  кандидатов с разным перекрытием;
- `normalize_caption` игнорирует `Hint`;
- `build_whisper_prompt` берёт оба вида;
- извлечение термина из диффа: короткая замена даёт термин, длинная нет;
- повышение области при повторе в другой встрече;
- миграция: существующие термины становятся `Replacement`.

Swift — только проигрывание фрагмента и связывание экрана.

## Чего в этой работе нет

- Автопредложения правок по уверенности Whisper (`token_data().p`) —
  требуют отдельного разбора: на редких терминах уверенность низкая
  всегда, и одной её мало.
- Правка живых субтитров. Только post-call: во время встречи выбирать
  из вариантов некогда.
