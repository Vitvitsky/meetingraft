# AGENTS.md — apps/macos/Sources/Audio

Захват звука: AVFoundation + Core Audio. Здесь живут ловушки молчаливой
потери звука и общих часов каналов.

## Файлы

`AudioCaptureCoordinator` (оркестрация, `@Observable @MainActor` —
**единственный** вызывающий `ingest_audio_chunk`/`startRecording`),
`AudioChunkPipeline`, `AudioTapping` (инъектируемый источник; умолчания
дают тривиально доступный микрофон, заглушки ничего не делают),
`MicrophoneCapture`, `SystemAudioCapture`, `PCMDownmixer`, `HostClock`,
`CaptureStartTiming`, `CaptureReadiness`, `AudioPermissions`,
`CaptureReadinessBadge`, `SystemAudioUnavailableBadge`.

## Часы и метки

- `HostClock`: `mach_absolute_time` — **единственные** часы, общие для
  микрофона и системного тапа (счёт кадров есть только внутри канала).
  Без них обе дорожки заявляли старт в ноль и расходились на 1150 мс.
  Считать **только разности**, никогда абсолют: тики с загрузки
  переполняют `UInt64` при умножении. Timebase: Apple Silicon 125/3,
  Intel 1/1.
- Метка чанка считается от **начала записи**, а не от нуля канала:
  `startOffsetMs + frame*1000/16000` (`AudioChunkPipeline`). Живой чанк —
  100 мс при 16 кГц, на диске — 2000 мс. `chunkDurationMs` не трогать
  (план 2026-08-06-audio-chunk-size).

## Ресемплер

`PCMDownmixer`: `AVAudioConverter` в 16 кГц моно Float32; ёмкость `+64`
кадра (замерено; больше — хуже, не поднимать); используется `.noDataNow`,
никогда `.endOfStream`, потому что конвертер **держит состояние** между
вызовами. Хвост в несколько мс поэтому остаётся внутри навсегда — метода
`drain()` нет, и тест утверждает, что отставание не превышает чанка на
сотне чанков.

## VPIO

Голосовая обработка macOS выключена по умолчанию
(`MicrophoneCapture.swift:7-22`): она захватывает устройство вывода и
ломает агрегат `SystemAudioCapture`, отчего второй канал тихо исчезает.
Включается только переменной `MEETINGRAFT_VOICE_PROCESSING=1` для замеров,
никогда — как настройка для человека.

## Системный звук

`SystemAudioCapture` использует `AudioHardwareCreateProcessTap` + приватное
агрегатное устройство + IOProc, **намеренно не ScreenCaptureKit** (тот
потребовал бы разрешения на запись экрана). SIGKILL оставляет tap и
агрегат в coreaudiod; `deinit` чистит их в обычном пути. Никогда не
подставлять недействительную метку канала (`SystemAudioCapture.swift:285`):
без метки канал получит неверную идентичность.

## Готовность и ошибки

Запрос и чтение разрешений инъектируются замыканиями — тестовый бандл не
может показать запрос. Бейдж готовности рисует только состояния-перечисления.
Тревога записи ключуется флагом `lastErrorIsMicrophone`, а не поиском
подстроки в тексте.

У сессий есть признак `channel_clock_unified`; записи до Epic 25 имеют его
`0` навсегда, и их сдвиг каналов не восстановить. `echo-probe` такие
записи судить отказывается.
